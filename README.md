# SkyBlock XP Optimizer Bot

A personal Discord bot that ranks the quickest non-monetary SkyBlock XP tasks a player can still do. See the v1 spec for full behaviour.

## Setup

```sh
npm install
cp .env.example .env   # fill in HYPIXEL_API_KEY (and Discord values once commands exist)
```

| Script | Does |
|---|---|
| `npm run check-api -- <username> [...]` | Build step 1 check: fetches profiles, writes `test/fixtures/API_CHECK.md` and raw fixtures |
| `npm test` | Unit tests (vitest) |
| `npm run typecheck` | Type-checks `src`, `scripts` and `test` |
| `npm run build` / `npm start` | Compile to `dist/` and run the bot |
| `npm run dev` | Run the bot with reload |

## Running on your PC (Windows)

Use this when the server is down or behind. **Stop the server copy first** (`pm2 stop xp-bot`), or both copies answer every command.

```powershell
npm ci                      # once, and after pulling dependency changes
copy .env.example .env      # once; fill in DISCORD_TOKEN, DISCORD_CLIENT_ID, HYPIXEL_API_KEY, DISCORD_GUILD_ID
npm run local               # registers /xp with Discord, then runs the bot and reloads on code changes
```

Ctrl+C stops it cleanly. Set `DISCORD_GUILD_ID` so command changes show up instantly instead of within the hour.

Links, ticks, exclusions and session rates live in `storage-data/` on whichever machine runs the bot. To keep yours, copy the server's folder over before starting, and copy it back before restarting the server:

```powershell
scp -r user@your-server:~/exp-bot/storage-data .    # server -> PC
scp -r storage-data user@your-server:~/exp-bot/     # PC -> server, with the server bot stopped
```

## Running on a Linux server (pm2)

Written for Ubuntu/Debian, such as a Contabo VPS. Run one copy only. Don't run the bot on your PC at the same time, or both copies answer every command.

```sh
# Once: Node 22 and pm2
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs
sudo npm install -g pm2
pm2 install pm2-logrotate            # caps pm2's own log files

# Once: in the cloned repo
cp .env.example .env && nano .env    # DISCORD_TOKEN, DISCORD_CLIENT_ID, HYPIXEL_API_KEY (+ DISCORD_GUILD_ID)
chmod 600 .env
npm ci
npm run build
npm run deploy-commands              # registers /xp with Discord
pm2 start ecosystem.config.cjs
pm2 save
pm2 startup                          # then run the command it prints, so the bot starts on reboot

# Each update
git pull && npm ci && npm run build && npm run deploy-commands && pm2 restart xp-bot

# Day to day
pm2 status
pm2 logs xp-bot
```

- **Back up `storage-data/`.** It holds links, ticks, rate overrides and measured session rates. `git pull` never touches it because it's gitignored.
- `logs/hypixel-requests.log` rotates itself at 10 MB, keeping one older copy as `.1`.
- On `pm2 stop`/`restart` the bot finishes pending storage writes before exiting.

## Build progress

- [x] **1. API check (code):** skeleton, Hypixel client, 60s profile cache / 24h resource cache, header-driven rate limiter that queues, keyed request log at `logs/hypixel-requests.log`
- [x] **1. API check (data):** fixtures for 3 players / 6 profiles in `test/fixtures/` (findings below)
- [x] **2. Profile normalizer:** `src/profile/`, tested against the fixtures. `npm run show-profile -- <player> [profile]` prints one.
- [x] 3. Task catalogue + `/xp coverage` (see "Task catalogue" below)
- [x] 4. Progress and status + `/xp overview player:<name> [profile]` (`npm run overview -- <fixture player> [profile]` prints it offline)
  - Readers in `src/tasks/readers/` (one per category) report a number and how far it can be trusted: `exact`, `lowerBound` (co-op member hidden) or `approx` (bestiary families).
  - `src/tasks/progress.ts` turns that into one status per task. The rules, in order:
    1. In Hypixel's completed-task list → verified complete.
    2. An exact or lower-bound number at the requirement → verified complete.
    3. An exact number short of it, or a one-time task missing from the list → verified incomplete. This clears a manual tick.
    4. Ticked → ticked.
    5. Approximate → estimated.
    6. No data → unavailable.
- [x] 5. Estimates and ranking + `/xp optimize [player] [profile]`: the top 10, 5 per page with Prev/Next. `npm run optimize -- <fixture player> [profile]` prints it offline.
  - Rates: `data/rates/*.json` are generated by `catalogue:build` from `data/sources/rate-defaults.json`. Values were researched on 2026-11-24 where possible. Each group's `basis` note says how a number was derived and which source it used, and anything still marked `PLACEHOLDER` is unresearched (Alchemy, Carpentry, Taming, Hunting, bestiary milestones).
    - Tune the bracket cut-offs in `data/rates/brackets.json`.
    - Hand-tune single activities in `data/rates/overrides.json`, which rebuilds never touch, or per profile with `/xp rate`.
  - Rate order: session (step 7) → `/xp rate` override → bracket default. A single number becomes a ±15% range.
  - Fixed minutes for fairy souls and minion crafts.
  - Bestiary rates scale with NEU's kill bracket, so a mob that needs 10× fewer kills per tier gets a 10× lower kills/min rate.
- [x] 6. Settings: `/xp link`, `/xp exclude`/`include`, `/xp tick`/`untick`, `/xp rate`. Saved as JSON in `storage-data/` (gitignored).
  - Links and exclusions are keyed by Discord user. Exclusions apply to every lookup.
  - `/xp exclude`/`include` take `category:`, `source:` (autocomplete), both, or neither (lists current exclusions). A source is one task group with all its tiers, such as "Wheat collection", "Revenant Horror Slayer" or "Bat Bestiary · Catacombs".
  - Excluded sources leave `/xp optimize` and the overview totals, and `/xp category` hides them with a count. `/xp task` still shows them, with a note. Tasks whose prerequisite is in an excluded source stay blocked.
  - Ticks and rate overrides are keyed by player UUID + profile ID, and only apply when looking at your linked profile.
  - `/xp tick` refuses tasks the API already proves done or not done. Ticks the API later contradicts are cleared on the next `/xp overview`.
  - `/xp rate` overrides are stored and validated against catalogue activities, but nothing reads them until step 5's `/xp optimize`.
- [x] 7. Sessions: `/xp session start <activity>`, `end`, `status`, plus `cancel`, which isn't in the spec.
  - Each start and end takes a fresh, uncached snapshot of the linked profile (2 keyed calls per session).
  - The rate is the change in the activity's metric ÷ minutes. Other metrics that moved are shown but not saved.
  - Collections use your own amount, so co-op mates don't inflate it.
  - Under 15 min is refused (the session stays open); over 4 h expires without saving.
  - New rates blend 60/40 with earlier ones, newest first, with the last 20 kept in `storage-data/sessions.json`.
  - Measured rates beat overrides and defaults in `/xp optimize` on your linked profile.
- [x] 8. `/xp category <category> [player] [profile]` and `/xp task <task>`.
  - Category view: each source's next tier, quickest first, 5 per page. It works for categories that are excluded or left out by default (minions), and prerequisites in other categories still apply.
  - Task detail: status and reason, progress, the estimate with its rate source, bracket and range, prerequisites with their status, next tier, and data source. It uses your linked profile, or shows task data only without a link.

- [x] 9. `/xp target xp:<n>` or `level:<n>` (plus `player`/`profile`): the quickest set of tasks to gain that much XP. `npm run target -- <fixture player> [profile] --xp N` (or `--level N`) prints it offline.
  - `level:` is the target level × 100 minus the profile's **total** SkyBlock XP (`leveling.experience`).
  - Runs on `PlanState` (`src/optimizer/plan.ts`), a simulated copy of the profile's progress. Each step completes tasks once, opens their next tiers and any task they unlock, and carries progress forward.
  - Greedy pick by XP per minute (midpoint estimate). When one task covers everything still needed faster than the best-ratio pick, that task is taken instead.
  - Trim pass: drops steps the target doesn't need, slowest first, only if replaying the plan from scratch still works (no prerequisite or shared progress lost), still reaches the target, and is quicker.
  - XP is exact (fixed rewards). Time is the sum of each step's range. Unreachable targets plan as far as eligible tasks go and say so. Stops at 5,000 steps.
  - Back-to-back tiers of one source show as one line ("Combat level 31→33"). 8 lines per page with Prev/Next.

- [x] 10. Unlocks and access. Sources are hypixelskyblock.minecraft.wiki (the main source from now on), fetched 2026-11-24.
  - **As prerequisites** (`data/sources/wiki-xp.json` `unlocks`; the planner can chain them):
    - Slayer bosses unlock from a tier of the previous boss. Tiers II–V need Combat 5/10/15/25, and tier V also needs slayer level 7. Riftstalker is exempt.
    - Dungeon floors need Combat 15 (Entrance) and Catacombs level 1–24, or 24–36 for Master Mode.
    - Dungeon-mob bestiary needs access to the first floor the mob appears on.
  - **Access checks** (`data/sources/access.json`, checked by `src/tasks/access.ts`):
    - Islands need skill or SkyBlock levels: Crimson Isle Combat 22, Dwarven Mines Mining 12, Galatea Foraging 12, the Garden SkyBlock level 5, the Rift SkyBlock level 12, and so on.
    - Sea creatures need their Fishing level. Island-locked collections need their area.
    - Kuudra needs Crimson Isle access, Elle's quest step and a key.
    - Heart of the Mountain tiers are checked against HOTM XP: Crystal Hollows needs HOTM 4, the Glacite Tunnels (Glacite, Tungsten, Umber) HOTM 7. This gate holds even when co-op collection progress shows in the area; only a done task is exempt.
    - Requirements the API doesn't show (Heart of the Forest tiers, quests, Safari Tickets, keys) count as met only when the profile already shows progress in that area. A task with progress of its own isn't blocked by these. Missing skill data counts as unmet.
    - Unlike prerequisites, these don't open up during an `/xp target` plan.
    - Not gated: event areas (festivals, Jerry's Workshop), Obsidian and Ice. Golem, Terracotta, Wither Guard and Wither Miner have no floor on the wiki, so they only need the Entrance.
  - **Minimum time per task** (`minMinutes` on rates, from `rate-defaults.json` `minimumMinutes`): one slayer boss for slayer XP, one dungeon run for Catacombs/class XP and dungeon-mob bestiary, one Kuudra run for Kuudra bestiary. The Kuudra run time is an estimate, because the wiki only gives per-wave timers.
  - **Enchanting** uses its own bracket cut-offs (10/30). Below 10 there are no Experiments, so the rate is enchanting at a table (~100–600 XP/min, estimate). The daily Experiment limit isn't modelled.

- [x] 11. Combined activities ("combos"): one action that progresses several sources at once.
  - [x] Data and loader: `data/combos/*.json`, loaded and validated at startup by `src/combos/combos.ts`. `npm run combos` lists them.
    - Each combo has a **primary** activity, whose existing rate is reused (session, override or bracket default), and **yields**. A yield is a ratio to the primary's unit, as a range, per bracket when it depends on gear. The primary's own metrics come from the tasks that use it.
    - Validation rejects the whole set on any problem: duplicate IDs, a primary with no rate or no tasks, a yield metric no task uses, a yield repeating the primary's metric, bad ranges, or a missing basis.
    - 138 combos, from hypixelskyblock.minecraft.wiki; all but the 8 floors are generated by `npm run catalogue:build`:
      - 43 gathering combos, **generated** by `npm run catalogue:build` into `data/combos/gathering.json` from `data/sources/combo-sources.json` (edit that file): every crop, ore and log whose block gives skill XP on the wiki. Skill XP per item = XP per block / (base items per block × (1 + fortune/100)), with fortune per bracket matching the collection rates. Base drops aren't on the wiki; the few that aren't 1 (carrots, lapis, ...) say where they came from. Crops are farmed in the Garden, so they also count toward crop milestones (1 per item, a floor checked against the fixtures).
      - 82 mob grinds (`data/combos/mobs.json`): one per grindable bestiary family with a Mob Drops Table on the wiki, read by `npx tsx scripts/fetch-wiki-mobs.ts` into `data/sources/wiki-mobs.json`. Combat XP and drops at 100% in every variant, per kill. Bosses, events, sea creatures, dungeons and Kuudra are left out; most Galatea Hunting creatures have no drops table yet.
      - 5 slayer quests (`data/combos/slayer.json`, from `combo-sources.json` `slayer`): Combat XP per slayer XP = Combat XP needed to spawn / slayer XP, at the bracket's tier. Where one mob is the usual spawn grind (Crypt Ghouls, Pack Spirits, Zealots, Blazes), its kills and drops come too: kills per slayer XP = that ratio / the mob's Combat XP.
      - 8 floors (Entrance–VII): base Catacombs XP per run.
      - No gathering combo for items with no block XP on the wiki (Hard Stone, Glacite, Tungsten, Umber, Sulphur, fishing).
    - All yields are floors (no Wisdom, Looting, score or boss-kill XP).
    - Not yet:
      - Class XP: the split isn't stated.
      - Master Mode: values look inconsistent.
      - The fandom wiki refuses automated fetches (HTTP 402), so it can't fill these gaps.
  - [x] Scoring (`src/combos/score.ts`), on `PlanState` without changing it:
    - A row runs at least until the primary's next open tier, then on to whichever upcoming tier (of the primary or any yield, up to 12 each) gives it the best XP per minute. So "Farm wheat in the Garden" runs to the next Farming level and collects the milestones and collection tiers on the way, instead of stopping at a 1 XP milestone.
    - Side yields count only at the low end of their ratio, so the row's XP is a floor. Excluded, monetary and already-claimed tasks earn nothing.
    - A row must finish tasks on two metrics, one a yield; otherwise it's a single task (a maxed collection plus one milestone is just the milestone). A combo whose primary is behind an access gate isn't offered, even if its side yields are open.
  - [x] `/xp optimize` (`rankWithCombos`):
    - Rows sit alongside single tasks, sorted the same way (by time, then XP), shown with ⚡.
    - The quickest entry claims its tasks, and later rows are re-scored without them, so a task appears once. Progress doesn't carry between rows. A row ties its primary task on time and wins on XP.
    - For established profiles combos are rarely in the top 10: they take longer than one-kill tasks.
  - [x] `/xp target`: combos compete with single tasks on XP per minute. Picking one applies all of it to the plan. Steps are replayed, so trimming keeps combos valid. Back-to-back rounds show as "⚡ Kill Zealots ×3".
  - [x] `/xp exclude activity:` / `include activity:`: never recommend that activity or a combo built on it. Unlike category and source exclusions, its tasks still count when something else finishes them.
  - [x] `/xp task` shows "Also progressed by" with the combos that feed the task.
  - [x] `/xp combos [player] [profile]`:
    - Every combo with something to do, best XP per minute first, 5 per page.
    - Each row stands alone: unlike `/xp optimize`, nothing is claimed between rows, so a row lists everything that combo would finish.
    - Combos with nothing to do right now, and ones whose activity you excluded, are named at the top.
  - [x] Sessions learn combo ratios:
    - A session on a combo's primary activity also measures each yield as change in the yield ÷ change in the primary. For example, Combat XP gained per Revenant slayer XP.
    - Ratios blend 60/40 with earlier ones, like rates, in `storage-data/sessions.json` under `ratios`.
    - On your linked profile a measured ratio replaces the data file's, as ±15% around it, with the low end still used for claims. ⚡ rows then say "your measured ratios".
  - [x] Sessions learn links: everything else that goes up during a session (skill XP, collections, bestiary, HOTM/HOTF XP, Garden XP and crop milestones) is saved as a ratio to the session's activity, under `links` in `sessions.json`. E.g. a Mithril session saves Mining XP and HOTM XP per Mithril.
    - A link joins scoring once it has moved in 2 sessions of that activity (one session can't tell a link from a minion or a co-op mate). It's added to the activity's combo, or makes a "<activity> (from your sessions)" combo when there's none. Linked profile only, like measured rates.
    - `/xp session end` lists what was linked and what's waiting for a second session; `/xp session status` lists the links in use.
  - [x] `/xp target` reuses a combo's row until one of its metrics changes (`PlanState.revisionKey`), so 138 combos plan quickly; the final plan is still replayed with every combo re-scored.
    - Yields that didn't move aren't saved: a zero usually means API lag, not a true zero.
    - Anything else done during the session counts too, so stick to the one activity.

## API check findings (2026-11-24)

- **`leveling.completed_tasks` exists**, but only holds one-time tasks: slayer first kills (`DEFEAT_ZOMBIE_SLAYER_ONE`), floor completions (`COMPLETE_CATACOMBS0`–`7`, `COMPLETE_MASTER_CATACOMBS1`–`7`), objectives, songs, essence perks, Abiphone, bank. Skills, collections, bestiary, minions and fairy souls never appear, so those need their own readers. A task entry can carry the Hypixel task ID so "verified complete" comes straight from the list.
- **Missing data cannot be told apart from never-played data**, apart from the cases below. Fresh or newly joined profiles omit `bestiary`, `slayer`, `dungeons`, `fairy_soul` and `crafted_generators` entirely. The normalizer marks these unavailable, never zero.
- **Collections API off**: `member.collection` is missing, but `player_data.unlocked_coll_tiers` is still there. Tier completion stays verifiable, and only the amounts are unknown.
- **Skills API off or no XP**: `player_data.experience` comes back as `{}` in both cases. It is treated as unavailable.
- **Inventory API off**: `inventory` only contains `bag_contents`. Not needed in v1.
- **Co-ops**: collection amounts are per member, and tiers use the co-op total. Members who left keep their data but have `profile.deletion_notice`, and they are excluded from the sum.
- Rate limit on the permanent key: 300 per window.

## Task catalogue

`data/tasks/*.json` is **generated**. Don't edit it by hand:

```sh
npm run catalogue:sources   # refresh data/sources/ (Hypixel resources live, NEU pinned to a commit)
npm run catalogue:build     # data/sources/ -> data/tasks/*.json + data/bestiary/families.json (validated)
npm run coverage            # print the /xp coverage report
npm run deploy-commands     # register /xp with Discord (DISCORD_GUILD_ID for instant updates)
```

| Category | Built from |
|---|---|
| Skills, Collections | Hypixel `resources/skyblock/*` (the "+N SkyBlock XP" in each level/tier's unlocks) |
| Bestiary | NEU `bestiary.json` families + `data/sources/bestiary-overrides.json`; XP per the wiki |
| Minions | NEU `misc.json` minion max tiers; per-tier XP and recipe unlocks from the wiki / collections resource |
| Slayer, Catacombs, Fairy Souls | `data/sources/wiki-xp.json` (hand-transcribed from the fandom wiki) + `data/leveling/` |

The official Hypixel Wiki closed in July 2026, so wiki values come from hypixel-skyblock.fandom.com.

The loader (`src/tasks/catalogue.ts`) rejects the whole catalogue if any entry is malformed. That covers shape, duplicate IDs, unknown prerequisites or cycles, an entry in the wrong category file, and non-monetary tasks in a "never" category. The bot won't start with an invalid catalogue.

**Known gaps and disagreements**

- **Bestiary:** NEU's families undercount real tiers by ~5% (Lime: 1,466 computed vs milestone 154 ≈ 1,540). Treat family tiers as estimates until checked in-game. Milestones come straight from the API.
- **Slayer:** the wiki's max is 30 XP above what its per-level table gives, so Riftstalker level XP is unverified. NEU also says spider level 2 needs 15 XP, where `data/leveling/slayer.json` says 25.
- **Minions:** the catalogue has 3,165 XP against the wiki's 2,963. NEU lists more minion tiers than the wiki counts.
- **Guide totals:** `data/meta.json` `guideCategories[].maxXp` is `null` until read from the in-game SkyBlock Leveling menu. Until then coverage shows `~` estimates and never reaches 100%.

## Hypixel client notes

- Keyed calls (`/v2/skyblock/profiles`) run one at a time. When `RateLimit-Remaining` drops to `HYPIXEL_RATE_LOW_WATER` or lower, the next call waits for `RateLimit-Reset`. A 429 waits for the reset and is retried up to 3 times.
- Each keyed request is logged as one JSON line: time, path, status, remaining, limit, duration. The key is never logged.
- Mojang username lookups are cached for 24h. That isn't in the spec, but it saves repeat lookups.
